## 模拟车辆采集（2026-09-07）

- 实时监控勾选“模拟车辆扫查”后，原时间间隔改为扫查间隔，默认建议5秒；车速单位mm/s，0表示静止。
- 每份完整FMC保存到会话received目录，经校验后生成frame_id和带时区扫查时间（内部字段仍为received_at），先写入scan_receipts数据库表，再加入容量8的串行成像队列。源数据副本与成像帧共用frame_id。
- 扫查与成像独立；积压时暂停模拟扫查，停止后排空已扫查队列并归档。低内存或磁盘不足时停止相关工作，保留已经落盘的记录；异常退出后的未完成记录保留用于排查，目前不自动恢复处理。
- 车速乘实际经过时间得到模拟扫查距离，仅作演示，不是编码器测量或缺陷全局坐标，不推断帧间连续缺陷。
- Agent的LangGraph末端增加报告证据审查，PDF写入前再次核对frame_id、扫查时间、处理时间顺序；报告附逐帧采集记录。
- 自动化测试覆盖独立接收、停止排空、队列上限、时间错配阻断。MATLAB真实连续演示仍需在开发桌面端验收；不承诺软件绝不崩溃。

> 下次开发首先提醒：团队负责成像、缺陷定位、长度/面积/方向计算和缺陷类别识别。本项目不再重复实现上述能力，主线调整为“检测结果质检、可信度审查、风险评价、标准知识库 Agent 和报告闭环”。在团队新接口稳定前，旧 YOLO-Seg 和 A扫分类代码只退出主链路，暂不直接删除。

## 一、职责边界

### 团队算法负责

- A扫/FMC数据解析与超声成像；
- 缺陷候选定位和真实物理坐标；
- 长度、面积、方向等二维定量结果；
- 裂纹、气孔、夹渣、未熔合等类别识别；
- 算法置信度、版本和必要的质量参数。

团队结果是定量值和类别的唯一权威算法来源。本项目不得使用 Agent、YOLO 或旧分类器覆盖团队结果。

### 本项目负责

- 团队结果包的接入、校验、存储和版本追溯；
- 原始数据、图像、缺陷结果和报告之间的唯一ID绑定；
- 输入质量检查、结果合理性检查和可信度审查；
- 基于透明规则的辅助风险评价；
- 本地权威知识库检索和受约束 Agent 解释；
- 人工复核、报告生成、历史归档和操作审计。

## 二、目标业务链路

```text
团队算法结果包
  -> 接口与完整性校验
  -> 数据质量检查
  -> 定量结果合理性与可信度审查
  -> 风险规则计算
  -> 标准/知识库检索
  -> Agent综合解释与一致性检查
  -> 人工复核
  -> 报告生成与归档
```

Agent只能解释已有证据、指出不确定性和提出复核建议，不能修改缺陷类别、位置、尺寸或直接给出无依据的合格/报废结论。

## 三、实施计划

### 阶段1：确定团队结果接口

- 与团队取得至少一份真实输出样例和字段说明。
- 定义版本化 `TeamInspectionPackage`，至少包含：
  - `schema_version`、`algorithm_version`；
  - `batch_id`、`frame_id`、`defect_id`；
  - 原始数据、成像图和辅助文件路径或引用；
  - 缺陷类别、类别置信度；
  - `x_mm`、`z_mm`、长度、面积、方向及其单位；
  - 数据质量、算法告警和处理时间。
- 明确空结果、部分失败、多缺陷和算法异常的表达方式。
- 保留适配层，团队以后更换成像程序时不改Agent和报告业务。

完成标准：同一缺陷在复核、Agent和报告中始终使用同一 `defect_id` 和同一组团队结果。

### 阶段2：数据与结果质量门控

- 检查文件完整性、通道数量、采样点、采样率和必要参数。
- 检查空通道、死通道、饱和削顶、明显低信噪比和处理失败。
- 检查坐标越界、单位错误、负尺寸、异常方向和重复缺陷记录。
- 检查类别、位置、尺寸和置信度字段是否完整。
- 输出固定状态：`可信`、`建议复核`、`数据不足`、`结果冲突`、`无法评价`。

完成标准：任何缺失或异常输入都不能静默进入Agent或正式报告。

### 阶段3：可信度审查

- 直接保留团队算法原始置信度，不擅自修改。
- 综合数据完整性、信噪比、边界位置、尺寸分辨率和算法告警生成独立的“结果可信度状态”。
- 团队结果与人工复核冲突时保留两者，不覆盖历史值。
- 数据积累后，可训练“结果是否需要复核”的辅助模型；没有可靠标签前先使用透明规则。

完成标准：操作者能区分“算法判定类别”和“系统认为该结果是否值得信任”。

### 阶段4：风险评价引擎

- 输入团队给出的类别、位置、深度、尺寸，以及材料、板厚、载荷和服役环境。
- 使用可追溯规则计算低、中、高、严重风险和建议动作。
- 风险分数必须列明触发项；缺少验收等级或服役条件时不得直接判定合格/报废。
- 风险规则与Agent提示词分离，由本地确定性代码执行。

完成标准：相同输入始终得到相同风险结果，Agent不能改变风险分数。

### 阶段5：受约束 Agent

- LangGraph节点调整为：读取结果、质量校验、可信度审查、知识检索、风险解释、一致性检查、报告草稿。
- 本地权威标准和项目知识库优先，联网资料只能作为补充并标明来源等级。
- 输出只保留操作者需要的信息：结论摘要、风险、原因、缺失条件和复核建议。
- API失败时生成本地规则摘要，不能阻塞复核和报告。

完成标准：Agent不得编造标准条款，不得把“未检出”写成“无缺陷”，不得覆盖团队和人工结果。

### 阶段6：复核、报告与归档

- 复核页面展示团队标注图、定量值、类别、质量告警和风险结果。
- 人工修改必须记录修改前后值、人员和时间。
- 报告继续沿用既定章节结构，只输出必要算法版本和有效结论，不写模型路径、API地址等开发信息。
- 历史批次保留结果包、人工复核、Agent来源和报告，不保留无价值缓存。

完成标准：报告中的每个缺陷都能反查到团队结果包和人工操作记录。

### 阶段7：旧能力退出与清理

- 团队接口通过完整冒烟测试后，停止主链路调用 YOLO-Seg 和 A扫类别分类器。
- 删除前先确认团队是否提供缺陷区域/标注图；若提供，YOLO不再保留运行价值。
- 旧模型、配置和依赖先移入兼容区，确认不再回退后再删除。
- 不修改团队成像和定量算法，只维护统一适配接口。

完成标准：主链路中不存在重复分类、重复定位和相互冲突的结果来源。

## 四、下一次开发前必须确认

1. 团队结果通过 JSON、MAT文件、CSV、数据库还是函数接口传递。
2. 一帧多个缺陷的结构和每个缺陷的唯一ID如何给出。
3. 团队是否输出标注图、掩膜或缺陷边界。
4. 团队是否输出类别置信度、定位误差或质量指标。
5. 哪些工件参数由操作者输入，哪些由团队算法提供。
6. 旧 YOLO-Seg 和 A扫分类器是暂时停用还是确认删除。

没有真实团队输出样例前，只建立接口和测试桩，不重写具体业务映射。

## 五、测试与验收

- 单元测试：结构校验、缺失字段、单位错误、坐标越界、重复缺陷、风险规则和Agent约束。
- 集成测试：团队结果导入、质检、复核、Agent、报告和历史归档。
- 降级测试：团队算法部分失败、Agent API失败、知识库无命中和报告写入失败。
- 一致性测试：复核页面、Agent和报告读取同一个缺陷记录，团队原始结果不可被静默覆盖。
- 隐私测试：API Key、本机绝对路径和原始敏感数据不得进入日志、仓库或报告。

## 六、当前边界

- 仿真数据只能用于开发验证，不能代表现场检测性能。
- 风险评价和Agent输出属于辅助意见，不替代持证检测人员和适用标准。
- 在团队接口稳定前，不删除旧能力的代码和模型；但新开发不得继续增强重复识别链路。
